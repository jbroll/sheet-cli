# drive-cli Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Drive-native `drive-cli` executable (copy/new/move/list/parents) plus matching MCP `drive_*` tools, and revert this session's `sheet-cli copy --into` additions so sheet-cli's TARGET grammar stays clean.

**Architecture:** A new `src/drive_cli/` package with a shared `ops.py` core (pure functions over `SheetsClient`) called by both `cli.py` (argparse) and the MCP server. Library primitives added this session (`copy_file`, `copy_folder`, `get_file_mime`) are kept; `_create_folder` is promoted to public `create_folder`; `list_files` and folder placement on `create()` are added.

**Tech Stack:** Python 3.8+, argparse, `sheet_client` (google-api-python-client), pytest.

## Global Constraints

- IDs are plain Drive file/folder IDs; destination folder is an **optional positional** argument (no `--into`).
- Mutations print JSON; reads (`list`, `parents`) are text-first with `--format=json`.
- Shared OAuth token at `~/.sheet-cli/token.json`.
- Tests run with `venv/bin/python -m pytest`.
